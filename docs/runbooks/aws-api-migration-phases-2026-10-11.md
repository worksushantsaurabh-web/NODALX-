## Phase 1 — local implementation

- `server/aws-api-http.mjs`: dispatches the current Vercel handlers from Node HTTP, keeps the inbound webhook stream raw, limits JSON to 1 MiB, and applies request timeouts. It binds to loopback through `scripts/start-aws-api.mjs`.
- `scripts/load-aws-api-secret.mjs`: reads one Secrets Manager JSON value through the EC2 instance role and refuses malformed, missing or process-control entries without logging values. `scripts/start-aws-api-from-secrets.mjs` loads it before importing the API.
- `scripts/package-aws-api.mjs`: copies 29 named source/config files to ignored `aws/build/api`. It copies no `.env`, credential cache or `node_modules`; install production dependencies on the host with `npm ci --omit=dev`.
- `aws/api-stack.yaml`: reviewable CloudFormation for a single t4g.small AL2023 ARM host, 20 GiB encrypted gp3, one Elastic IP, HTTPS/HTTP-only API SG, and a private SG-to-SG RDS rule. It uses a separately bootstrapped, tightly scoped instance profile for SSM and staging-secret read access. The template leaves the current public RDS rule untouched. Validated and deployed in Phase 3.
- `aws/nodalx-api.service` and `aws/nodalx-caddy.service` run on the AL2023 host. `NODALX_API_SECRET_ID` is in root-owned `/etc/nodalx-api/bootstrap.env`; it contains only the ARN. The actual JSON secret lives in Secrets Manager. Caddy overwrites `X-Forwarded-For` with the remote peer to prevent client spoofing of the support relay's per-process limiter. Set `SUPPORT_EMAIL_ALLOWED_ORIGINS` to the exact production/Preview origins before routing browser traffic through the external hostname.

Initial staging secret should select `DATA_BACKEND=rds` and include the RDS URL, hosted `SUPABASE_URL` and publishable key. Keep intake, outbound mail, processing, Make and workspace inbound gates disabled until the corresponding staged tests. Copy additional server-only settings from Vercel by name and reviewed value through the AWS console; never print or commit them. The restricted API database role must support only the required app tables and `SET ROLE authenticated/service_role` flows; verify grants in a disposable database before replacing the current `postgres` login.

CloudFront can shorten repeat liveness requests at nearby edge locations, but it cannot improve real application traffic until the API route actually uses the distribution; uncached requests still go to the US East origin.

`aws/api-staging-cloudfront.yaml` is a validated staging distribution template.
